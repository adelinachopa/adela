## Введение

"Escape to EMK" - это 2D платформер на PyGame с кооперативным режимом для двух игроков. Проект использует модульную архитектуру и современные практики разработки.

### Основные технологии
- **Python 3.8+** - основной язык программирования
- **PyGame 2.5.0+** - игровой движок
- **JSON** - хранение данных уровней и сохранений
- **Модульная архитектура** - разделение ответственности

### Блоки (взаимодействие)

Блоки - это интерактивные объекты, которые игрок может поднимать и бросать. Они определяются в секции `blocks` уровня.

#### Параметры блока:
- `x`, `y` - координаты левого верхнего угла
- `width`, `height` - размеры блока (по умолчанию 40x40)
- `color` - цвет блока в формате [R, G, B] (используется если нет изображения)
- `image` - путь к изображению (например, `"image/sprite/PK.jpg"`)

#### Механика взаимодействия:
1. **Поднятие блока**: Игрок (Аделина) может поднять блок, находясь рядом с ним (коллизия хитбоксов) и нажав клавишу "вниз" (по умолчанию `K_DOWN`). Блок поднимается над головой игрока и устанавливается в состояние `carried_by`.
2. **Перенос блока**: Пока игрок несёт блок, блок жёстко привязан к позиции над головой игрока (`rect.midbottom = player.rect.midtop`). Коллизии блока с платформами игнорируются, чтобы избежать телепортации.
3. **Бросок блока**: При повторном нажатии клавиши "вниз" (с учётом кулдауна) игрок бросает блок в направлении своего движения. Блок получает начальные скорости `throw_vx` (горизонтальная) и `throw_vy` (вертикальная вверх) и летит по параболической траектории с гравитацией `GRAVITY = 0.5`.
4. **Защита от мгновенного броска**: В классе `Player` реализован таймер `pickup_cooldown` (10 кадров), который предотвращает:
   - Мгновенный бросок сразу после поднятия
   - Повторное поднятие сразу после броска
5. **Коллизии брошенного блока**:
   - При движении вниз (`throw_vy > 0`): блок приземляется на платформу, сбрасывает состояние броска (`thrown = False`) и останавливается.
   - При движении вверх (`throw_vy < 0`): блок останавливается у нижней границы платформы (`rect.top = platform.rect.bottom`) и обнуляет вертикальную скорость.
   - После обработки коллизии с одной платформой цикл прерывается (`break`), чтобы избежать множественных коррекций позиции.
6. **Толкание блока**: Если персонаж (игрок или враг) движется и сталкивается с блоком, блок толкается в том же направлении. Логика толкания учитывает разницу центров (`dx`) и скорость сущности.
7. **Взаимодействие с кнопками**: Блок (включая блок PK) может активировать кнопки (`Button` и `VerticalButton`), если блок не переносится (`carried_by is None`) и не брошен (`thrown == False`). Это позволяет использовать блоки как грузы для нажатия кнопок.

#### Класс Block:
Блоки реализованы как класс `Block` (наследник `Entity`) в `entities.py`. Класс содержит методы `pick_up()`, `throw()` и обновление состояния.

#### История исправлений проблем с блоками:
В процессе разработки были выявлены и исправлены следующие проблемы:

1. **Толкание блока не работало** (Фаза 10): Ошибка в определении направления толкания. Исправлена логика: теперь блок толкается, когда игрок движется в сторону блока.
2. **Блок телепортировался при поднятии** (Фаза 12): Игрок удерживал клавишу вниз, и блок сразу же бросался в следующем кадре. Добавлен кулдаун `pickup_cooldown = 10`.
3. **Блок падал сквозь землю после броска** (Фаза 13): При броске использовалась переменная `throw_vy`, а не `vy`, поэтому коллизия с платформами не обрабатывалась. Исправлена логика в `_check_collision`.
4. **Блок телепортировался/застывал при броске вверх** (Фаза 14): Проблема в множественных коррекциях позиции из-за обработки коллизии с несколькими платформами. Добавлен `break` после обработки первой коллизии.
5. **Перемещение персонажа при падении блока** (Фаза 15): Обнаружена ошибка в логике - при падении блока на персонажа код перемещал персонажа вниз. Исправлено в методе `check_entity_collisions`.
6. **Резкое изменение координат блока** (Фаза 16): Причина - неправильная начальная позиция блока (Y=570 вместо Y=535) и отсутствие ограничения максимальной скорости падения. Исправлено:
   - Изменена начальная позиция блока в JSON
   - Добавлено ограничение максимальной скорости падения `MAX_FALL_SPEED = 15`
   - Добавлен флаг `on_ground` для предотвращения применения гравитации на земле
7. **Проблема с падением блока на игрока** (Фаза 17): Приоритет горизонтальной коллизии над вертикальной приводил к толчку игрока. Исправлено добавлением проверки на падение блока перед определением типа коллизии.
8. **Проблема с управлением поднятием блока** (Фаза 18): Оба игрока могли поднимать блоки. Исправлено добавлением проверки наличия клавиши 'down' в controls игрока.
9. **Коллизия с врагом при запуске игры** (Фаза 19-20): Враг, вероятно, падал под карту и сталкивался с игроком. Временно удалён из уровня.
10. **Исчезновение Аделины с экрана** (Фаза 21): Аделина падала вниз за пределы экрана из-за неправильной начальной позиции. Её координата Y=610 размещала её ниже платформы, что приводило к бесконечному падению. Исправлено изменением Y на 485, что соответствует позиции на платформе (платформа y=575, высота игрока 90).

#### Добавление блока в уровень:
Добавьте секцию `blocks` в JSON файл уровня как показано в примере выше.

### Кнопки и двери

#### Кнопка (Button)
- Открывает/закрывает дверь с соответствующим `door_id`.
- Реагирует на коллизии с игроками и блоками (если блок не переносится и не брошен).
- При нажатии вызывает `door.open()`, при отпускании - `door.close()`.

#### Вертикальная кнопка (VerticalButton)
- Управляет вертикальным движением блока (`MovingBlock`) с соответствующим `block_id`.
- Реагирует на коллизии с игроками и блоками.
- При нажатии вызывает `block.start_moving()`, при отпускании - `block.stop_moving()`.

#### Дверь (Door)
- Может быть горизонтальной или вертикальной.
- Плавно открывается/закрывается изменением размеров.

#### Движущийся блок (MovingBlock)
- Двигается вертикально вверх или вниз при активации кнопки.
- Имеет ограничение перемещения (`max_offset`).

#### Дверь выхода (DoorExit)
- Активируется, когда оба игрока находятся в её зоне.
- Запускает завершение уровня с UI интерфейсом.

## Обработка ошибок

### Система логирования

Все ошибки записываются в `game_errors.log`:
```
[2026-05-04 10:30:15] [ERROR] Level.load_level: File not found: levels/missing.json
```

### Использование в коде

#### Безопасная загрузка изображений
```python
from error_handler import GameErrorHandler

surface = GameErrorHandler.load_image_safe(
    "image/sprite/character.png",
    width=50,
    height=50,
    default_color=(255, 255, 255)  # Белый цвет при ошибке
)
```

#### Декоратор для безопасного выполнения
```python
from error_handler import safe_execute

@safe_execute(default_return=None, context="Обработка игрока")
def process_player(player):
    # Код, который может вызвать исключение
    return player.update()
```

#### Ручное логирование
```python
from error_handler import log_error, log_warning, log_info

log_info("Уровень загружен", "GameLoader")
log_warning("Медленная загрузка текстуры", "ResourceManager")
log_error("Столкновение не обработано", "PhysicsEngine")
```

### Восстановление после ошибок

Система обеспечивает:
1. **Fallback значения** - при ошибке загрузки используются значения по умолчанию
2. **Уровень по умолчанию** - если не удалось загрузить уровень
3. **Продолжение работы** - большинство ошибок не приводят к крашу игры

## Новые функции (2026-05-21)

### Система сохранения прогресса
- Реализован модуль `save_manager.py` для управления сохранениями.
- Данные сохраняются в JSON файл `save.json`.
- Сохраняются: имя игрока, общее количество собранных питончиков, прогресс по уровням (пройден/не пройден, количество собранных питончиков, общее количество питончиков на уровне).
- При повторном прохождении уровня сохраняется максимальное количество собранных питончиков.
- Сохранение происходит при успешном завершении уровня (активация двери выхода) и при проигрыше.

### Экран проигрыша
- При столкновении с врагом появляется UI `LevelFailUI` с красноватым фоном.
- Кнопки "Меню" (возврат в главное меню) и "Начать заново" (перезагрузка уровня).
- Прогресс сохраняется (уровень отмечается как пройденный, если ранее был пройден).

### Взаимодействие блока PK с кнопками
- Блоки (включая блок PK) теперь могут активировать кнопки (`Button` и `VerticalButton`).
- Условие: блок не должен быть перенесён (`carried_by is None`) и не должен быть брошен (`thrown == False`).
- Модифицированы методы `update` классов `Button` и `VerticalButton` для приёма параметра `blocks` и проверки коллизий с блоками.
- Обновлены вызовы в `levels.py` для передачи группы блоков в кнопки.

### Улучшения UI
- `LevelCompleteUI` и `LevelFailUI` используют полупрозрачные overlay.
- Кнопки имеют hover-эффект (изменение цвета при наведении).
- UI экраны обрабатывают события мыши и клавиатуры.
