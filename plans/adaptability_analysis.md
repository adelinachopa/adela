# Анализ адаптивности игры "Escape to EMK" под разные экраны ПК

## Текущее состояние: адаптивность ОТСУТСТВУЕТ

Игра жёстко завязана на разрешение **1280×720** и не адаптируется под другие экраны.

---

## 1. Жёстко заданное разрешение экрана

**Файл:** [`setting.py:7-8`](setting.py:7-8)
```python
SCREEN_WIDTH = 1280
SCREEN_HEIGHT = 720
```

Все размеры, позиции и координаты рассчитываются относительно этих констант. При изменении разрешения экрана:
- Фоны масштабируются (через `pygame.transform.scale`) — **но с искажением пропорций**
- Позиции элементов UI рассчитываются по `SCREEN_WIDTH // 2` — **смещаются**
- Координаты платформ, врагов, дверей в JSON-уровнях — **абсолютные, не масштабируются**

---

## 2. Проблемные места

### 2.1 Создание окна ([`main.py:133-141`](main.py:133-141))
```python
screen = pygame.display.set_mode(
    (SCREEN_WIDTH, SCREEN_HEIGHT),
    pygame.FULLSCREEN | pygame.SCALED
)
```
- `pygame.SCALED` масштабирует содержимое до размера окна, **но соотношение сторон 16:9 фиксировано**
- На мониторах с другим соотношением (16:10, 4:3, 21:9) появятся **чёрные полосы** или изображение будет обрезано
- В windowed mode (`main.py:141`) масштабирования нет вообще

### 2.2 Меню ([`menu.py`](menu.py))
- Кнопка "Play" позиционируется по центру: `SCREEN_WIDTH // 2, SCREEN_HEIGHT // 2 + 25`
- Заголовок: `SCREEN_WIDTH // 2, SCREEN_HEIGHT // 4`
- **При изменении разрешения** кнопка и заголовок сместятся пропорционально, но фоновое изображение (`main_page.jpg`) будет искажено

### 2.3 Выбор уровня ([`level_select.py`](level_select.py))
- Кнопки уровней позиционируются по центру: `start_x = (SCREEN_WIDTH - total_width) // 2`
- Размер кнопок: **150×150 px (фиксированный)**
- **На маленьких экранах** кнопки могут не поместиться или быть слишком большими
- **На больших экранах** кнопки будут казаться маленькими

### 2.4 JSON-уровни ([`levels/level_01.json`](levels/level_01.json), [`levels/level_2.json`](levels/level_2.json), [`levels/level_3.json`](levels/level_3.json))
- **Все координаты абсолютные** (в пикселях 1280×720)
- Пример: платформа `{"x": 0, "y": 680, "width": 1280, "height": 40}` — рассчитана на ширину 1280
- При смене разрешения платформы **не будут соответствовать** новому размеру экрана
- Игроки, враги, collectibles — все координаты жёсткие

### 2.5 UI завершения уровня ([`entities.py:1074-1178`](entities.py:1074-1178))
- `LevelCompleteUI` принимает `screen_width` и `screen_height`, но они берутся из `DoorExit`, который получает их из JSON уровня (по умолчанию 1280×720)
- Кнопки имеют **фиксированный размер** (200×60, 200×50)
- Позиции рассчитываются относительно переданных размеров, но если переданы 1280×720, а экран 1920×1080 — кнопки будут в неправильном месте

### 2.6 UI проигрыша ([`entities.py:1181-1250`](entities.py:1181-1250))
- Аналогичная проблема: фиксированные размеры кнопок, позиции относительно 1280×720

### 2.7 Индикатор питончиков ([`main.py:339-341`](main.py:339-341))
```python
indicator_x = SCREEN_WIDTH - 200
indicator_y = 20
```
- Жёсткая позиция в правом верхнем углу

### 2.8 Кнопка рестарта ([`main.py:180-181`](main.py:180-181))
```python
restart_button_image = load_image("image/sprite/refresh.jpg", 100, 100)
restart_button_rect = restart_button_image.get_rect(topleft=(20, 20))
```
- Фиксированный размер 100×100, фиксированная позиция (20, 20)

---

## 3. Что работает (частично)

- **`pygame.SCALED`** в полноэкранном режиме — масштабирует содержимое, но с фиксированным соотношением 16:9
- **`load_image()`** — масштабирует изображения под заданные размеры, но размеры везде жёсткие
- **`LevelCompleteUI` и `LevelFailUI`** — принимают размеры экрана параметрами, но получают их из JSON (1280×720)

---

## 4. Вывод

**Игра НЕ адаптивна.** Она рассчитана строго на разрешение 1280×720 (16:9). На других разрешениях:
- **На меньших экранах** (1024×768, 1366×768) — элементы могут не помещаться, текст обрезаться
- **На больших экранах** (1920×1080, 2560×1440) — всё будет мелким и расположенным в левом верхнем углу (в windowed mode) или растянутым с искажением (в fullscreen с SCALED)
- **На не-16:9 экранах** — чёрные полосы или обрезание

---

## 5. Рекомендации по реализации адаптивности

### Вариант A: Минимальный (сохранение 16:9)
1. Определять реальное разрешение экрана через `pygame.display.Info()`
2. Вычислять масштабный коэффициент: `scale = min(real_w / 1280, real_h / 720)`
3. Создавать surface 1280×720, рендерить всё на него, затем масштабировать на реальный экран
4. Добавить letterboxing (чёрные полосы) для не-16:9 экранов

### Вариант B: Полная адаптивность
1. Все размеры и координаты хранить в **относительных единицах** (процентах от экрана)
2. При загрузке уровня пересчитывать координаты под текущее разрешение
3. UI-элементы позиционировать относительно реального разрешения
4. Размеры шрифтов делать относительными (`font.Size(int(screen_height * 0.05))`)
5. Передать реальные `screen_width` и `screen_height` во все UI-компоненты

### Вариант C: Режим окна с изменением размера
1. Использовать `pygame.RESIZABLE` вместо `FULLSCREEN`
2. На событие `VIDEORESIZE` пересоздавать surface и пересчитывать все позиции
3. Хранить коэффициенты масштабирования как глобальные переменные
