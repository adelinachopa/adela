## Этап 4: Исправление бага #1 — `pygame.init()` возвращает кортеж

- **Файл**: [`main.py:112`](main.py:112)
- **Проблема**: `pygame.init()` возвращает кортеж `(numpy.ndarray успешно, n ошибок)`, а не `bool`. Проверка `if not pygame.init():` всегда `False`.
- **Исправление**: Заменить на:
  ```python
  pygame.init()
  ```
  (без проверки) или на:
  ```python
  success, fail = pygame.init()
  if fail > 0:
      print(f"WARNING: {fail} module(s) failed to initialize")
  ```

---

## Этап 5: Исправление бага #2 — Несоответствие хитбокса и визуала

- **Файл**: [`entities.py:29`](entities.py:29)
- **Проблема**: `self.rect.inflate_ip(...)` уменьшает rect после создания, но изображение (`self.image`) остаётся прежнего размера. Хитбокс меньше визуала.
- **Исправление**: Либо не уменьшать rect, либо создать отдельный хитбокс (`self.hitbox`), либо масштабировать изображение под новый rect.

---

## Этап 6: Исправление бага #3 — Диагональные коллизии в `Player.collide`

- **Файл**: [`entities.py:169-182`](entities.py:169-182)
- **Проблема**: При коллизии по диагонали (одновременно `dx` и `dy` не равны 0) могут сработать несколько условий `if`, что приводит к некорректной позиции. Например, при движении вправо-вниз сработают и `dx > 0`, и `dy > 0`.
- **Исправление**: Использовать `elif` вместо `if` для взаимного исключения, или разделить обработку по осям.

---

## Этап 7: Исправление бага #4 — `break` в `Block._check_collision`

- **Файл**: [`entities.py:396`](entities.py:396)
- **Проблема**: `break` после обработки первой платформы — если блок пересекается с несколькими платформами, обрабатывается только первая. Блок может провалиться сквозь вторую платформу.
- **Исправление**: Убрать `break` и обрабатывать все коллизии, или использовать `continue` для перехода к следующей платформе.

---

## Этап 8: Исправление бага #5 — Идентификация персонажей по цвету

- **Файл**: [`entities.py:1015-1021`](entities.py:1015-1021)
- **Проблема**: `DoorExit.update()` идентифицирует персонажей по жёстко заданным цветам `(0, 100, 255)` для Аделины и `(255, 100, 100)` для Ани. Если у игрока другой цвет, логика сломается.
- **Исправление**: Добавить атрибут `player_id` или `name` в класс `Player` и использовать его для идентификации.

## Этап 10: Исправление бага #7 — Отсутствуют поля врага в `get_default_level()`

- **Файл**: [`level_loader.py:242-247`](level_loader.py:242-247)
- **Проблема**: В `get_default_level()` у врага нет обязательных полей `speed`, `jump_power`, `patrol_range`. При загрузке уровня по умолчанию это вызовет ошибку `KeyError`.
- **Исправление**: Добавить поля со значениями по умолчанию:
  ```python
  "enemies": [
      {
          "x": 600,
          "y": 600,
          "speed": 2,
          "jump_power": 0,
          "patrol_range": [500, 700]
      }
  ]
  ```
