# План исправления ПК-версии "Escape to EMK"

## 1. 🔴 main.py — Критические баги

### 1.1. `pygame.init()` возвращает кортеж, а не bool
**Файл:** [`main.py:112`](../main.py:112)
**Проблема:** `pygame.init()` возвращает `(n_success, n_failed)`. Условие `if not pygame.init()` всегда False.
**Исправление:** Заменить на `if pygame.init()[1] > 0`.

### 1.2. `pygame.FULLSCREEN | pygame.SCALED` на ПК
**Файл:** [`main.py:186-189`](../main.py:186)
**Проблема:** На ПК флаг `SCALED` может работать некорректно — игра может растягиваться или не на весь экран.
**Исправление:** Для ПК использовать `pygame.FULLSCREEN | pygame.HWSURFACE | pygame.DOUBLEBUF`, для мобильных — `pygame.FULLSCREEN | pygame.SCALED`.

### 1.3. Отладочный спам в консоль каждый кадр
**Файл:** [`main.py:318-323`](../main.py:318)
**Проблема:** Каждый кадр в лог пишется состояние всех игроков — замедляет игру, забивает лог-файл.
**Исправление:** Убрать отладочный вывод или сделать его опциональным (через DEBUG-флаг).

### 1.4. Мёртвый код — `generate_level_from_template()`
**Файл:** [`main.py:17-108`](../main.py:17)
**Проблема:** Функция генерации уровней из шаблона нигде не вызывается.
**Исправление:** Удалить функцию или вынести в отдельный модуль.

### 1.5. Закомментированный старый код
**Файл:** [`main.py:529-693`](../main.py:529)
**Проблема:** ~165 строк закомментированного кода с преподавателями и прямоугольниками.
**Исправление:** Удалить.

## 2. 🟡 entities.py — Баги логики

### 2.1. `Block._check_collision` — break после первой коллизии
**Файл:** [`entities.py:396`](../entities.py:396)
**Проблема:** После обработки коллизии с первой платформой цикл прерывается. Если блок пересекается с несколькими платформами, обрабатывается только первая — блок может "проваливаться".
**Исправление:** Убрать `break` или переработать логику для обработки всех коллизий.

### 2.2. `DoorExit.update` — жёсткая привязка к цветам
**Файл:** [`entities.py:1015-1021`](../entities.py:1015)
**Проблема:** Активация двери выхода проверяет цвета игроков (BLUE=Аделина, RED=Аня). Если цвет изменится — дверь не активируется.
**Исправление:** Проверять по индексу игрока в группе `self.players` (первый = Аделина, второй = Аня).

### 2.3. `LevelCompleteUI` и `LevelFailUI` — огромные кнопки
**Файл:** [`entities.py:1098-1099`](../entities.py:1098), [`entities.py:1199-1200`](../entities.py:1199)
**Проблема:** Кнопки 400x250px. На 1280x720 три кнопки (400*3+20*2=1240px) едва помещаются. На мобильных с меньшим разрешением не влезут.
**Исправление:** Сделать размеры кнопок адаптивными (процент от ширины экрана).

## 3. 🟡 levels.py — Баги загрузки уровня

### 3.1. `solid_objects` не включает `blocks`
**Файл:** [`levels.py:457-460`](../levels.py:457)
**Проблема:** `solid_objects` включает только `platforms`, `doors`, `moving_blocks`. Блоки не включены — игроки могут проходить сквозь них.
**Исправление:** Добавить `self.blocks` в `solid_objects`.

### 3.2. `scale_pos` и `scale_size` модифицируют оригинальные данные
**Файл:** [`levels.py:58-66`](../levels.py:58)
**Проблема:** Функции изменяют объекты внутри `data` напрямую. При перезагрузке уровня данные могут быть уже изменены.
**Исправление:** Создавать копии объектов перед масштабированием.

## 4. 🟡 menu.py — Мелкие баги

### 4.1. Нет обработки закрытия окна во время отрисовки
**Файл:** [`menu.py:57-65`](../menu.py:57)
**Проблема:** Если окно закрывают между вызовами `handle_events()`, игра не реагирует.
**Исправление:** Добавить проверку `pygame.QUIT` в цикле `run()`.

## 5. 🟡 level_select.py — Жёстко закодированные уровни

### 5.1. Жёстко закодированные имена уровней
**Файл:** [`level_select.py:34`](../level_select.py:34)
**Проблема:** `level_ids = ["level_01", "level_2", "level_3"]` — при добавлении нового уровня нужно менять код.
**Исправление:** Сканировать папку `levels/` автоматически, сортировать по номеру.

### 5.2. Жёсткая цепочка разблокировки
**Файл:** [`level_select.py:60-72`](../level_select.py:60)
**Проблема:** Логика разблокировки закодирована: level_01 -> level_2 -> level_3.
**Исправление:** Сделать универсальную логику: уровень N разблокирован, если уровень N-1 пройден.

## 6. 🟢 setting.py — Избыточность для ПК

### 6.1. `android_log()` вызывается при импорте на ПК
**Файл:** [`setting.py:114-120`](../setting.py:114)
**Проблема:** На ПК `android_log()` пишет в `game_debug.log` и выводит в консоль — захламляет.
**Исправление:** Вызывать `android_log()` только при `IS_MOBILE`.

### 6.2. `load_image()` — избыточная сложность для ПК
**Файл:** [`setting.py:227-371`](../setting.py:227)
**Проблема:** 8 путей поиска + BytesIO fallback. На ПК достаточно `pygame.image.load()`.
**Исправление:** Для ПК — упрощённая версия `load_image()`, для мобильных — полная с fallback.
